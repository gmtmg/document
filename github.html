アプリ作るための基本とか›GitHubってなに？

アプリを作る人が、みんな使っているGitHubってなに？

GitHub（ギットハブ）は、アプリのファイルを「セーブ」して「みんなで共有」するための場所です。ゲームのセーブにたとえて説明します。

先に答えを3行で
  1. Gitは、ファイルの変更をセーブする道具（自分のパソコンの中）。
  2. GitHubは、そのセーブを預けて、みんなで共有するインターネット上の倉庫。
  3. アプリ作りは「書く → セーブ → GitHubに送る」のくり返し。
Chapter 0 ／ そもそもの前提

そもそも、何に困っているの？

GitHubは「困りごと」を解決するための道具です。まず困りごとから見ていきます。

アプリは、たくさんのファイル（文字が書かれたデータ）でできています（前提5）。アプリを作るとは、そのファイルを何度も何度も書き直していくことです。

何度も書き直していると、レポートや資料を作るときと同じ困りごとが起きます。こんな経験、ありませんか？

企画書.docx 企画書_修正.docx 企画書_修正_最新.docx 企画書_最新_田中さん確認済み.docx 企画書_本当に最終.docx 企画書_本当に最終(1).docx
困りごと1：どれが最新？

コピーが増えて、どれが正しいのかわからなくなる。

困りごと2：元に戻せない

「昨日の方がよかった」と思っても、上書きしていたら戻せない。

困りごと3：みんなで直すとぶつかる

2人が同じファイルを同時に直すと、片方の変更が消えてしまう。

ひとことで言うとアプリのファイルは、文書よりずっと数が多く、何百回も書き直します。
だから「いつ・誰が・どこを変えたか」を自動で記録してくれる道具が必要です。それがGitとGitHubです。

Chapter 1

Gitは、ファイルの「セーブ機能」

ひとことで言うとGit（ギット）は、ゲームのセーブのように、ファイルの状態をいつでも記録して、いつでも戻れるようにする道具です。
セーブすることを「コミット」と呼びます。

ゲームでボス戦の前にセーブするように、アプリ作りでも「ここまでできた」というところでセーブ（コミット）します。コミットするときは「何をしたか」のメモを付けます。

下で実際にやってみましょう。自己紹介ページのファイルを書き換えて、メモを付けてセーブしてください。右の記録を押すと、その時点の中身と「どこが変わったか」が見られます。

ファイル：自己紹介.txt（書き換えてみよう）

セーブの記録（新しい順）
    選んだセーブで変わったところ

    緑 は追加された行、赤 は消された行です。

    覚えておくことコミット ＝ メモ付きのセーブ。いつでも前のセーブに戻れるので、安心して書き直せる。

    Chapter 2

    GitとGitHubは、別のもの

    ひとことで言うとGitはセーブ機能、GitHubはセーブデータを預ける倉庫。
    ゲームでいえば、本体のセーブとクラウドセーブの関係です。

    Git（ギット）

    ゲーム本体のセーブ機能

    • 自分のパソコンの中で動く道具
    • ファイルの変更をセーブ（コミット）する
    • インターネットがなくても使える
    • 無料の道具

    GitHub（ギットハブ）

    クラウドセーブ ＋ みんなの集会所

    • インターネット上のサービス（Webサイト）
    • Gitのセーブデータを預けておける
    • パソコンが壊れても、データが残る
    • 仲間と同じデータを共有して、一緒に作れる

    「リポジトリ」は、プロジェクトの箱

    GitHubでは、1つのアプリ（プロジェクト）ごとに「リポジトリ」という箱を作ります。リポジトリには、ファイルとセーブの記録がまとめて入っています。このサイトも document という名前のリポジトリに入っています。

    GitHubと似たサービスに GitLab などもありますが、いちばん多くの人が使っているのがGitHubです。

    覚えておくことGit ＝ 手元のセーブ機能。GitHub ＝ セーブを預けて共有する倉庫。リポジトリ ＝ プロジェクトごとの箱。

    Chapter 3

    GitHubに送る・受け取る

    ひとことで言うと自分のセーブをGitHubに送るのが「プッシュ」、GitHubから最新のセーブを受け取るのが「プル」です。

    あなたと友達の2人で、同じアプリを作っているとします。2人のパソコンと、真ん中にGitHub。ボタンを押して、セーブ（丸いしるし）がどう移動するか見てください。

    あなたのパソコンGitが入っている

    GitHubインターネット上の倉庫

    友達のパソコンGitが入っている

    試してみるとわかるとおり、GitHubに新しいセーブがあるときは、先にプルしないとプッシュできません。これは「友達の変更を知らないまま上書きして、消してしまう」事故を防ぐためのルールです。第0章の「困りごと3」の答えです。

    覚えておくことセーブ（コミット）→ プッシュで送る → 仲間はプルで受け取る。

    Chapter 4

    ブランチとプルリクエスト

    ひとことで言うとブランチは、本番をコピーして作る「下書き用の世界線」。
    プルリクエストは、「この下書きを本番に入れていいですか？」というお願いです。

    みんなが使っているアプリを直接書き換えて、もし壊れたら大変です。そこで、本番（mainと呼ばれることが多い）はそのままにして、別の世界線（ブランチ）で作業します。うまくいったら、仲間にチェックしてもらってから本番に合体（マージ）させます。

    「次へ」で、1ステップずつ見てみましょう。

    本番（main）
    下書き（ブランチ）

    たとえるなら

    覚えておくことブランチで作る → プルリクエストでチェックしてもらう → マージで本番に合体。本番はいつも安全。

    Chapter 5

    実例：このサイトもGitHubで作られている

    ひとことで言うとこのシリーズのファイルも、GitHubのリポジトリ gmtmg/document にセーブされています。

    このサイトは、ClaudeというAIが作りました。そのときの流れは、このページで学んだことそのままです。

    1. ブランチを作る：claude/ai-beginner-learning-site-… という名前の下書きの世界線を作った
    2. コミットする：ファイルを書いて、メモ付きでセーブした
    3. プッシュする：GitHubに送った

    実は最初、プッシュは「権限がありません」と断られました。GitHubは「このリポジトリに書き込んでいいのは誰か」をきちんと管理しているからです。持ち主が許可を出してから、プッシュできました。

    実際のセーブの記録（一部）
    1. 4e08209Add AI app learning site for beginners
      AIアプリの学習サイトを追加
    2. 10aeeb2Make the learning site easier for beginners
      初心者向けにもっとやさしく
    3. 最新Add series top page and GitHub / online lessons
      トップページと、このページを追加

    左の英数字はセーブごとに付く番号（ID）です。メモは英語で書く習慣の人が多いです。

    GitHubでできること、まとめ

    • セーブを預ける：パソコンが壊れても安心
    • みんなで作る：プッシュ・プル・プルリクエストで共同作業
    • サイトを公開する：「GitHub Pages」という機能で、リポジトリのファイルをそのままWebサイトとして公開できる
    • 他の人のコードを見る：世界中の人が公開しているコードを読んだり、使ったりできる
